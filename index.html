What it isA door that checks the ID before it opens

Most systems take a request in, parse it, and only then decide whether to trust it. The parser runs on an attacker’s bytes before anyone knows who sent them, and that is where injection, deserialisation and malformed-input attacks live. break-it turns the order round:

  1. Verify before parse. Each record arrives as a small signed packet. The gate checks its size, its magic number, its exact layout, the sender, the Ed25519 signature and the sender’s counter, in that order, on the raw bytes. Only then is it read. One failure and the record is refused, with the stage and the reason.
  2. A living immune system. Every refusal is written to a hash-chained journal, classified into a family and fingerprinted. If it can never become valid, it becomes an exact antibody that drops the same bytes on sight; its shape teaches the family. Nodes pinned to each other share antibodies, and each re-runs them on its own gate before trusting one.
  3. The rebound. A source the gate keeps refusing must attach proof-of-work before it is even looked at. The price rises with its own refusals (4,096 hashes a look past 100 refusals, 262,144 past 500); the gate checks the work in one hash and sends nothing back.
  4. A referee. Behind the gate sits a deliberately naive app. A referee written separately from the gate watches every admitted message against an independent grammar and the ledger. If anything malicious ever reaches the app, the referee says so. That is the only way to win.

Words used on this page
Record, packet
One item of the feed (here: one client’s payment in one month), sent as a small packet of bytes with a header, the record and a signature.
Ed25519 signature
A 64-byte proof, made with the sender’s private key, that the sender made these exact bytes. Anyone with the public key can check it; nobody without the private key can make one.
Counter
A number in every packet that must be exactly one more than the sender’s last. A copied packet arrives with a number already used, so a replay is refused.
Verify before parse
Check the bytes are well-formed and signed by a known sender before any software reads what they say.
Antibody
A record of an attack the gate refused, kept so the same bytes are dropped on sight next time and similar ones are recognised by family.
Proof-of-work
A small puzzle a source must solve by trying many hashes. The rebound makes a repeat attacker solve one before each look; checking the answer takes one hash.
Ledger, journal
Two append-only files where each line commits to the one before it, so nothing can be removed or changed unnoticed. The ledger holds what was admitted; the journal holds what was refused and why.
fsync
Forcing a write all the way to the disk before going on, so an admitted record survives a crash.
Referee
Separate code that checks every admitted record against its own rules and the ledger. It decides whether anything got through that should not have.

    The herd · living defenceA zero-day lands once. Then every node closes the hole itself

    Every defence has a flaw nobody has found yet. When an attacker finds one in the gate, the same flaw is in every node, because every node runs the same code. Before this change, a breached node shared the attack with its peers, but a peer will not refuse bytes its own gate admits (no defence may ever turn on genuine traffic), so the same attack landed once on every node. Now the herd shares the proof instead.

    1. It lands once. A packet the gate admits reaches the app. The referee checks every admitted message with its own grammar, written apart from the gate, and this one breaks it: a breach.
    2. The proof travels. The node switches its referee’s grammar on as a stage of its door, writes the packet to its journal, and shares it with its peers, signed, at once.
    3. Each peer checks it itself. A peer takes nobody’s word for it. It runs the packet through its own gate and its own grammar. Only if its gate accepts the packet’s form and its grammar rejects it, a zero-day proven on the peer itself, does it switch the grammar on too.
    4. The hole closes for the whole family. From then on every node refuses at its door anything its grammar rejects: the same packet, and every variant of it.
    5. Nothing genuine pays for it. A genuine record passes both checks, so it is admitted as before. A peer that shares a genuine record as if it were an attack proves nothing and patches nothing. The proof is kept in each node’s journal and checked again at every restart.

    Measured, sealed first, on five real nodes

    To measure what the herd does with a zero-day, we planted one: in the measuring process alone, a module hook loads the gate with its period limit off by one, so it accepts period 1200, a month past its limit. The shipped gate is untouched. The attack is the attack kit’s own out-of-range record, signed with the ingest key: the stolen-key case. The patch also closes only what the independent grammar can see: a flaw in both validators at once would not be caught this way.

      How it worksOne record’s path, traced from the pilot

      The numbers on the diagram come from the pilot’s receipt: what the real node did with the feed and the six injected attacks.

      1. Limits first. The HTTP layer refuses a body without an exact Content-Length, a chunked body, anything over 336 bytes, and more than 300 requests a second from one address (bursts to 600). Nothing is parsed yet.
      2. On sight. The packet’s SHA-256 is looked up in the exact-antibody library. A known attack is dropped here, after one hash, and the gate double-checks it would refuse it anyway, so an antibody can never block a genuine record.
      3. The rebound. A source past 100 gate refusals must attach a proof-of-work token bound to this packet and this ten-second window. The gate checks it in one hash. The pilot’s feed never owed anything.
      4. The gate. Size, magic number and version, the exact layout of the payload, a pinned sender, the Ed25519 signature over a domain prefix and the bytes, then the counter, which must be exactly the last one plus one. A REC record is 11 bytes: an account (1–99,999,999), a month (January 2000 to December 2099) and an amount (0–100,000,000), each checked as an integer on the bytes.
      5. The sentinel. Verified traffic can still be wrong if a key is stolen. The sentinel watches each sender’s behaviour on Gary W. Floyd’s GEP ladder: a drain, a destruction run, posting over 10,000,000 in 64 records, or a mix that deviates from the sender’s own baseline is throttled, stepped up or blocked.
      6. The ledger, then the app. The packet is written to a hash-chained ledger and fsync’d before the app sees it. On restart every packet is run through the gate again; one altered byte and the node refuses to start.
      7. The referee. After every admitted message, the referee checks it with its own grammar and the ledger, and checks the app’s state is a replay of the ledger. This is the win oracle, and nothing else decides a break.
      8. Every refusal teaches. The journal records the stage, the reason, the family and a fingerprint. Refusals that can never become valid mint exact antibodies; each is signed and sent to pinned peers, which re-run it on their own gates before adopting it.

      Security, data protection and audit

      • UK GDPR by design. The records stay on your machine. There is no processor, no international transfer and no telemetry. The gate reads only the record’s own fields.
      • Audit. Every admitted record is in a hash-chained ledger, fsync’d before the app acts; every refusal is in a hash-chained journal with its stage, its reason, its family and its fingerprint. Both are plain JSON lines.
      • Keys. Each sender has its own Ed25519 key; the node holds only public keys. Rotating a key changes the key set, and antibodies bound to the old one stop firing for key-dependent stages.
      • Fail-closed. Any error inside the gate refuses. A ledger the gate would refuse stops the node from starting.
      • Explained. In the pilot every refusal, in the HTTP answer and in the journal, named its stage and gave its reason in words.
      • Where the node sits. It listens on the machine’s own loopback address, so it has no port on your network. Whatever already brings the feed to you (your TLS endpoint, VPN or file drop) hands each record to the node on the same machine, and your network edge stays exactly as you run it today.
      • What is read before the gate. Node’s own HTTP layer reads the request line and headers, capped at 8 KB, with a 2-second header and 3-second request timeout, a required Content-Length and no chunked bodies. The record itself is not read by anything until every gate stage has passed.
      • Signed, not hidden. A signature proves who sent a record and that no byte changed; it does not hide the record. Confidentiality on the wire is the TLS you already run in front.

      Risks, answered straight

      “One address is limited to 300 records a second.”
      By design, with bursts to 600, so one source cannot crowd out the rest. A partner that sends faster sends from more addresses, or you run more nodes; the cost case adds nodes for your volume.
      “How fast is one node?”
      In the pilot, on one laptop, every record had its signature checked and was fsync’d to disk before the app saw it, at the rate the receipt shows. Disk sync is the ceiling; a server disk raises it.
      “Our partners don’t sign records.”
      They need a signing adapter at their end. That is what makes verify-before-parse possible: there is nothing to verify in an unsigned record.
      “A partner’s key is stolen.”
      The sentinel watches verified behaviour; in the battery a stolen feed key posting credit without end is blocked at record 5. Rotate the key and the node stops trusting the old one.
      “What if the gate has a hole?”
      The referee is written separately from the gate and checks every admitted message. A breach becomes an antibody at once, is pushed to every pinned peer, and mints a signed rune; the record of it is the fix’s test.
      “How does a partner reach a node on loopback?”
      Through what already carries the feed to you. Your TLS endpoint, VPN or file drop runs on the same machine and passes each record to the node. The node never needs a port on the network, so it adds nothing to your attack surface there.
      “A partner sends a record wrongly by mistake.”
      It is refused with its stage and reason, written to the journal, and the partner resends it correctly with the next counter. Mistakes cost a partner nothing: the rebound starts only after 100 refusals.
      “High availability?”
      One node writes one ledger, under a lock. For capacity or a second site, run more nodes, each with its own ledger, pinned to each other.

      White paperVerify before parse, measured

      1 · The problem

      An ingest service’s first act is to parse. The parser is the largest piece of code that ever touches an attacker’s bytes, and it runs before any decision about who sent them. Rules that inspect a request after it has been parsed come too late for the attacks that live in the parse itself, and they cannot tell a forged or replayed record from a genuine one when the bytes look ordinary.

      2 · The design

      Each record is a fixed-layout packet: a 16-byte header (magic number, version, sender, a 64-bit counter, the payload length), a payload whose exact grammar is fixed per operation, and a 64-byte Ed25519 signature over a domain prefix and everything before it. The gate checks the stages in order on the raw bytes, and the canonical parser is total: for every packet the gate accepts, encoding its parse gives back the same bytes, so no packet can be read two ways. The sentinel then judges behaviour per verified sender; the ledger is written and synced before the app acts; the referee checks the app against the ledger and an independent grammar.

      3 · The immune system

      Each refusal is an antigen: classified into a family, fingerprinted, written to a hash-chained journal. Refusals at stages that can never become valid (size, magic, schema, sender, signature, replay) mint exact antibodies keyed by the packet’s hash and bound to the pinned key set; every refusal adds a shape antibody that recognises the family by distance in feature space. Negative selection: a node adopts an antibody only after its own gate refuses the antigen, so a peer cannot make it reject genuine traffic. Shares are signed and batched, so a flood of unique forgeries cannot make the mesh do unbounded work.

      4 · The rebound law

      A source that has been refused 100 times owes a proof-of-work token per packet (12 leading zero bits, about 4,096 hashes), 500 times 18 bits (about 262,144). The token is bound to the time window, the source and the packet, so it cannot be precomputed or reused. The defender checks it in one hash. The law holds three ways, all tested: no amplification at the defender, the attacker spends at least as much as the defender, and the price never falls as refusals rise. Nothing is emitted back at the source.

      5 · The method

      The estate’s organ pattern: seal, measure, judge. The pilot’s claims were committed to git before the measuring code existed, and the measurement refuses to run if a claim file differs from its commit. The judge is a pure function under the mutation gate. Failed claims are kept on the page with what was measured. The egress meter proves it can see with a canary before its zero is trusted.

      6 · Results

      See the pilot section above: each sealed claim with its measured value, the run’s machine and timing, and the history of the attempts, including the first full run that stopped because the sender exhausted Windows’ ephemeral ports.

      7 · What it is not

      It is not a general web firewall: it guards one exact wire format, and a partner writes that format through an adapter. It is not a replacement for keeping private keys safe: the holder of a sender’s key is that sender, which is why the sentinel watches verified behaviour. One node writes one ledger.

The page's cost case uses your own volumes with dated list prices: at AWS's own worked example of one web ACL, 19 rules and 10 million requests a month, WAF is $30.00 and a REST API Gateway adds $35.00, while one node drawing the laptop chip's 55 W maximum all month costs £10.57 at the Ofgem cap for October to December 2026.
      What counts as breaking it?
      The referee decides, and it is written independently of the gate. You win if the app acts on a message the gate never admitted, if the gate admits a packet an independent grammar rejects, if an action does not match its ledger entry, or if the app's state stops being a replay of the ledger. A win mints a signed Breaker's Rune.
